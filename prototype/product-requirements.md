# 蜂汇智理 产品需求说明（原型 v0.1）

- 负责人：AI 3 产品原型与演示工程师
- 所属轮次：第一轮
- 文档状态：第一轮交付，仿真数字为占位
- 目录所有权：本文档及 `prototype/` 全部内容由 AI 3 维护

---

## 1 产品定位

**蜂汇智理**：新就业群体参与城市治理的 AI 协同与仿真平台。

骑手和网约车司机通过语音、照片和位置快速上报城市问题，AI 完成脱敏、合并、分类和建议分派；
治理人员人工确认并反馈处置结果；仿真端比较不同反馈与激励机制的治理效果。

一句话演示口径：

> 新就业群体用 30 秒完成一次上报，AI 把口语变成结构化线索，治理人员保留最终决定权，
> 处置结果回到上报人手中，并连接服务型激励。

## 2 目标用户与角色

| 角色 | 使用端 | 真实身份 | 原型中的处理 |
| --- | --- | --- | --- |
| 骑手 / 网约车司机（上报人） | 骑手端 | 新就业群体 | 虚构用户 `R-1001`「示例骑手 A」 |
| 社区 / 街道 / 市治理人员 | 治理端 | 处置与分派责任人 | 虚构坐席「示例治理坐席」 |
| 仿真操作者 | 仿真端 | 团队成员 / 评委 | 无需登录 |

原型不建立真实账号体系，不使用手机号、姓名、车牌、住址等个人标识。

## 3 核心研究问题（与冻结底稿一致）

> 什么样的 AI 上报、处置反馈和服务激励机制，能够在不明显增加新就业群体时间成本与隐私风险的情况下，
> 提高城市问题的有效上报率、处置效率和持续参与意愿？

产品原型的作用是**把这四个机制可视化、可演示**，不是证明其效果。效果判断由 AI 2 的仿真实验负责。

## 4 四个机制情景（产品侧映射）

| 编号 | 名称 | 产品上体现为 | 原型中的入口 |
| --- | --- | --- | --- |
| S0 | 现状基准 | 无统一入口、无分类、无持续反馈 | 仿真端基准列；骑手端「现状对照」说明 |
| S1 | AI 上报 | 一键上报 + AI 脱敏 / 分类 / 合并 / 建议分派 | 骑手端上报流程 + 治理端 AI 建议卡 |
| S2 | AI 上报 + 透明反馈 | 增加责任主体、处理进度、结果反馈 | 骑手端「处理进度和结果」页 |
| S3 | S1 + S2 + 差异化激励 | 增加积分、驿站权益、托管优先权 | 骑手端积分与权益、治理端反馈动作 |

产品原型默认运行在 S3 机制组合下，用户可以在仿真端切换比较。

## 6 第一版明确不做

- 真实城市级导航、路径规划、实时路况。
- 自动处理交通事故、人身安全、火灾、治安事件；这类事件只做提示与转接，不进入普通工单流。
- 宣称已接入政府、物业、外卖平台或网约车平台生产系统。
- 改造商业平台派单算法。
- 未经审核的全城小区地图；原型地图为**示意底图 + 虚构网格**。
- 真实账号、真实支付、真实积分兑换、真实短信或推送通道。

## 7 功能需求

### 7.1 骑手端

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| P-01 | 首页提供语音 / 图片 / 文字 / 位置四个上报入口 | 四个入口均可在 1 次点击内到达上报页 |
| P-02 | 上报页支持组合输入（语音 + 照片 + 位置 + 补充文字） | 至少一种输入即可提交；无输入时按钮禁用 |
| P-03 | 提交前必须先经过 AI 识别与用户确认 | 不能从上报页直接跳到进度页 |
| P-04 | 确认页展示脱敏结果、结构化要素、类别、风险、重复候选 | 五类信息同屏可见 |
| P-05 | 用户可修改 AI 建议的类别与描述 | 修改后治理端显示「上报人已修改」 |
| P-06 | 紧急级别事件展示应急转接卡，不进入普通流程 | 卡片包含 110 / 119 / 120 / 122 与提示文案 |
| P-07 | 进度页展示责任主体、当前状态、时间轴 | 时间轴包含 AI 处理、人工确认、分派、处置、反馈节点 |
| P-08 | 结果反馈展示处置结果与激励 | 已办结事件展示积分变化 |
| P-09 | 服务查询展示社区末端服务点信息 | 服务点均为虚构示例，标注“演示数据” |

### 7.2 治理端

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| G-01 | 事件列表支持筛选与状态标记 | 风险、状态、处置主体可筛选 |
| G-02 | 地图视图展示事件分布与重复聚合 | 重复事件以聚合标记展示数量 |
| G-03 | 详情页突出 AI 建议，且与人工决定视觉分离 | AI 区块使用虚线边框与「AI 建议」标签 |
| G-04 | 人工决定提供确认分派 / 退回补充 / 转交三选一 | 每个动作都有明确结果文案 |
| G-05 | 确认分派必须由人工选择处置主体 | AI 建议不能自动成为决定 |
| G-06 | 处置结果可填写并回传上报人 | 反馈内容出现在骑手端时间轴 |
| G-07 | 指标概览区分「可演示口径」与「待仿真」 | 无实验依据的指标显示占位标记 |
| G-08 | 紧急事件在治理端有独立提示 | 列表与详情均显示应急渠道提示 |

### 7.3 仿真端

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| S-01 | 可选择 S0 / S1 / S2 / S3 | 四个情景均可切换，仅新增机制不同 |
| S-02 | 展示六项固定指标对比 | 六项指标全部出现，单位与方向明确 |
| S-03 | 参数与假设可展开查看来源标注 | 每个参数标注「来自材料」或「项目假设」 |
| S-04 | 结果局限说明常驻可见 | 明确说明占位状态与合成数据性质 |
| S-05 | 占位数据醒目标记 | 所有数值前有 `PLACEHOLDER_SIM_RESULT` 标记与横幅 |

## 8 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可演示性 | 打开 `prototype/app/index.html` 即可运行；无构建步骤、无外部依赖、可离线 |
| 稳定性 | 演示流程确定性；相同操作产生相同结果；可一键重置 |
| 时长 | 三分钟内可完成一次完整治理闭环（见 `demo-script.md`） |
| 数据 | 全部为虚构或脱敏数据；无真实个人信息；无密钥 |
| 可解释性 | AI 的每一条建议都显示依据（命中的规则、距离、相似度） |
| 隐私 | 遵循最小必要原则；脱敏在本地演示逻辑中完成，示例不采集真实音视频上传 |
| 免责 | 每个 AI 输出区块标注「AI 建议，需人工确认」 |

## 9 数据规则

1. 全部测试数据虚构或脱敏，见 `prototype/test-data/`。
2. 仿真结果未产生时使用 `PLACEHOLDER_SIM_RESULT`，页面同时显示「占位数据，不是实验结果」。
3. 不编造真实访谈、真实统计、真实系统接入。
4. 不把 30 人定性访谈写成总体比例。
5. 不把 AI 生成角色和模拟结果冒充真实调查。
6. 地图为示意底图，网格编号虚构，不代表真实行政区划。

## 11 已知局限

- AI 能力由规则表模拟，不是真实模型推理；命中规则的演示性大于准确性。
- 定位为虚构网格，不接入真实地理编码。
- 积分与驿站权益为虚构示例，不存在真实兑换关系。
- 仿真端全部数值为占位，须在第二轮由 AI 2 结果替换（见 `technical-flow.md` 第 6 节替换清单）。
- 未做无障碍与多端适配的完整验证，只保证桌面浏览器演示稳定。
