## 2 旁白合规检查（录完逐条听）

| # | 检查句 | 通过标准 |
| --- | --- | --- |
| 2.1 | 是否说过「已接入某平台 / 某部门系统」 | 必须**没有**；只能说「原型以虚构数据演示交互流程」 |
| 2.2 | 是否把占位数字说成实验结果 | 必须**没有**；必须说「占位数据，不是实验结果」 |
| 2.3 | 是否声称 AI 自动分派或自动处置 | 必须**没有**；必须说「AI 只给建议，人工确认」 |
| 2.4 | 是否给出准确率、成功率等未经评估的数字 | 必须**没有** |
| 2.5 | 是否把 30 人定性访谈说成比例 | 必须**没有**；原型中不出现该表述 |
| 2.6 | 紧急镜头是否说明「平台不替代法定应急渠道」 | 必须说到 |
| 2.7 | 是否出现真实姓名、手机号、车牌、真实住址 | 必须**没有**（画面中出现的均为虚构演示值） |

## 4 常见返工与定点补录

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 数据被上一轮操作改乱 | 未先点「重置演示数据」 | 点重置后只补录受影响的那一镜 |
| 录到了空白的详情页 | 未选事件就直接录制 | 用带 ID 的路由 `#/gov/events/T-20260312-07` 重录该镜 |
| 应急卡没出现 | 用了普通事件文本 | 用 `#/rider/ai-review?input=emergency` 或控制台「载入场景 → 紧急事件」 |
| 旁白说错数字 | 口误或记错占位值 | 停下来重说该句，或直接改说「占位数据，具体数值以仿真实验结果为准」 |
| 画面字体过小 | 窗口过小或缩放非 100% | 恢复 1440×900 以上窗口、缩放 100% 后重录该镜 |
| 需要重新生成截图 | 原型有改动 | `node prototype/app/shot.js`，再核对 `screen-list.md` 第 5 节 |

## 5 录屏后交接动作

```powershell
git status
git diff
git add prototype
git commit -m "prototype: 清楚说明本次成果"
git push
```

- 不执行 `git push --force`，不执行 `git reset --hard`，不修改 `main` 分支。
- 只提交 `prototype/` 目录；`evidence/`、`simulation/`、`integration/`、`submission/` 保持只读。
- 录屏素材（大文件）按需交付，**不要**把原始录像提交进仓库（见协作指南第 18 节）。

## 6 第二轮替换后的重录范围

当 AI 2 仿真结果替换占位数字后，只需重录：

| 需要重录 | 原因 |
| --- | --- |
| 镜 8（仿真端） | 数字与结论变化，旁白需改为「模型显示…」 |
| 镜 5（进度页） | 若反馈文案或积分规则有调整 |
| 报告中的全部仿真端截图 | 需重新运行 `node prototype/app/shot.js` |

其余镜头（骑手端上报、AI 确认、治理端人工决定、应急转接、服务查询）不依赖仿真数字，**无需重录**。
