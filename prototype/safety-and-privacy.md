# 蜂汇智理 安全、隐私与演示数据声明（原型 v0.1）

- 负责人：AI 3
- 所属轮次：第一轮
- 用途：说明原型的隐私设计、AI 能力边界、应急转接规则和演示数据性质

---

## 1 三条不可越过的线

| 线 | 内容 |
| --- | --- |
| 法定应急线 | 火灾、治安、人身伤害、交通事故等严重事件，必须提示联系 **110 / 119 / 120 / 122**；AI 与平台不替代法定应急渠道，不自动处置 |
| 人工决定线 | AI 只输出**建议**；确认、分派、退回、转交、办结必须由治理人员人工决定 |
| 数据真实线 | 全部演示数据虚构或脱敏；不声称接入任何政府、物业、外卖或网约车平台生产系统 |

## 2 应急转接设计

### 2.1 触发条件

描述命中以下词表任意一项即进入紧急分流：

```text
火灾 起火 抽烟起火 冒烟 燃气泄漏 煤气 打架 斗殴 伤者 受伤 流血 晕倒
交通事故 撞车 撞人 触电 漏电 高空坠物 坍塌 塌方 有人被困 溺水 治安
```

### 2.2 界面行为

1. 风险等级直接置为「紧急」，并说明命中原因。
2. 确认页顶部出现红色应急卡，列出四个号码及其适用场景：
   - **110** 治安、纠纷、可疑人员
   - **119** 火灾、被困、危险品泄漏
   - **120** 人员受伤、身体不适
   - **122** 道路交通事故
3. 主按钮文案改为「我已联系法定渠道，继续留存线索」。
4. 提示文案固定为：

> 严重事故、火灾或治安事件请立即联系 110 / 119 / 120 / 122。
> 本平台不替代法定应急渠道，也不会自动处置此类事件。

5. 提交后工单带 `emergency` 标记，治理端列表与详情页显示应急提示条，处置路径不进入普通自动建议。

### 2.3 不做什么

- 不自动拨打、不发短信、不触发任何真实报警流程。
- 不对紧急事件做「自动分派」或「自动办结」。
- 不承诺响应时间。

## 3 隐私设计

### 3.1 数据最小必要

| 数据 | 原型是否采集 | 说明 |
| --- | --- | --- |
| 语音 | 否（不录音、不上传） | 演示使用预置转写文本，界面明确标注「演示转写」 |
| 照片 | 本地选择，不上传 | 演示用本地图片或内置示例图，页面无网络请求 |
| 精确位置 | 否（不调用定位接口） | 使用虚构网格选择器，坐标为演示坐标 |
| 姓名、手机号、车牌 | 否 | 测试数据中不出现真实标识 |
| 车牌 / 门牌等正文信息 | 仅在演示中展示脱敏效果 | 示例为虚构号码，脱敏后立即遮蔽 |

### 3.2 脱敏规则

| 规则 | 处理 | 界面呈现 |
| --- | --- | --- |
| 手机号 | 保留前 3 位后 2 位，其余遮蔽 | 「已脱敏：手机号」 |
| 车牌 | 保留省份简称与首字母 | 「已脱敏：车牌」 |
| 身份证 | 整段移除 | 「已移除：身份证号」 |
| 微信号 / QQ | 替换为「联系方式已隐藏」 | 「已脱敏：联系方式」 |
| 精确门牌 | 保留到楼栋号，去掉户号 | 「已降精度：门牌」 |
| 疑似真实姓名 | 替换为「某先生 / 某女士」 | 「已脱敏：姓名」 |

脱敏结果在**提交前**由上报人确认，上报人可以看到原意是否被曲解。

### 3.3 演示环境声明

页面顶部常驻声明条：

> 原型演示环境 · 演示数据为虚构或脱敏 · 不代表真实系统接入 · AI 输出仅为建议

`prototype/test-data/` 中每个文件头部包含 `_notice` 字段，重复声明数据性质。

## 4 AI 能力边界声明

| 说法（禁止） | 允许的说法 |
| --- | --- |
| AI 自动分派工单 | AI 输出建议处置主体，由治理人员确认分派 |
| AI 判断责任单位 | AI 给出建议层级与理由，责任认定由人工决定 |
| AI 已接入城市治理平台 | 原型以虚构数据演示交互流程，未接入任何生产系统 |
| AI 识别准确率 95% | 原型使用规则表演示可解释流程，未做准确率评估 |
| 系统可处理交通事故 | 交通事故等严重事件提示转接 122/110/120，平台不处置 |

## 5 演示数据声明

1. 骑手身份 `R-1001`「示例骑手 A」为虚构角色。
2. 事件、工单号、网格编号、服务点、驿站名称均为虚构。
3. 地图为示意底图，**不代表真实行政区划**，不包含未经审核的小区地图。
4. 积分、权益、托管优先权为虚构示例，不存在真实兑换关系。
5. 仿真端全部数值为占位（`PLACEHOLDER_SIM_RESULT`），不是实验结果，必须由 AI 2 结果替换。
6. 不使用真实访谈原话；不把 30 人定性访谈写成总体比例。
7. 不展示任何真实企业、政府机构或平台的名称作为合作方。

## 6 原型内的安全文案（逐字稿）

以下文案在页面中固定出现，录屏与答辩口径应保持一致：

| 位置 | 文案 |
| --- | --- |
| 顶部声明条 | 原型演示环境 · 演示数据为虚构或脱敏 · 不代表真实系统接入 · AI 输出仅为建议 |
| AI 建议区 | AI 建议，需人工确认。模型输出不构成行政决定。 |
| 应急卡 | 严重事故、火灾或治安事件请立即联系 110 / 119 / 120 / 122。本平台不替代法定应急渠道。 |
| 仿真端横幅 | 占位数据，不是实验结果。数值用于演示界面结构，须由仿真实验最终结果替换。 |
| 服务查询 | 以下服务点与权益为演示数据，不代表真实驿站或真实权益。 |
| 积分区 | 积分为演示数值，用于展示激励机制界面。 |

## 7 录屏与材料安全

- 录屏中不得出现真实姓名、手机号、车牌、真实住址、聊天记录截图。
- 录屏使用浏览器干净配置文件，避免书签栏、历史记录泄露。
- 不使用真实访谈录音；不展示 `.env`、密钥、账号信息。
- 截图由脚本本地生成，不含浏览器 UI，避免泄露个人信息与桌面内容。

| AI 建议与人工决定是否视觉分离 | 是 |
| 页面是否发起外部网络请求 | 否 |
| 测试数据是否含真实个人信息 | 否 |
| 仿真数字是否全部带占位标记 | 是 |
| 是否声明未接入生产系统 | 是 |
| 是否包含「AI 提高准确率 X%」类未经证实的表述 | 否 |
