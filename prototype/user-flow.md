## 1 端到端主流程（治理闭环）

```text
[骑手端]                        [AI 处理]                       [治理端]                [骑手端]
发现问题
  │
  ├─ 语音 / 文字 / 照片 / 位置  ──► 脱敏
  │                                  │
  │                              结构化要素
  │                                  │
  │                              重复检测与合并建议
  │                                  │
  │                              类别建议 + 风险分级
  │                                  │
  │ ◄──── AI 识别结果 + 用户确认 ─────┘
  │            │
  │            ├─ 紧急级别 ──► 应急转接卡（110 / 119 / 120 / 122），退出普通流程
  │            │
  │            └─ 普通级别 ──► 生成工单 ──► 事件列表 / 地图
  │                                              │
  │                                          AI 建议分派（社区 / 街道 / 市级）
  │                                              │
  │                                     人工决定：确认分派 / 退回补充 / 转交
  │                                              │
  │                                          处置与结果录入
  │                                              │
  │ ◄──── 责任主体 + 进度 + 结果反馈 ─────────────┘
  │
  └─ 积分与服务型权益更新 ──► 持续参与意愿
```

## 2 骑手端流程

### 2.1 正常上报

| 步骤 | 页面 | 用户动作 | 系统反馈 |
| --- | --- | --- | --- |
| 1 | 首页 | 点击「语音上报」等入口 | 进入一键上报页，入口类型预选 |
| 2 | 一键上报 | 按下语音（演示：播放预置转写） | 出现转写文本 |
| 3 | 一键上报 | 点击「AI 识别」 | 进入识别中状态（约 0.8 秒演示延时） |
| 4 | AI 识别与确认 | 核对脱敏结果与结构化要素 | 展示 5 类 AI 输出 |
| 5 | AI 识别与确认 | 可修改类别或描述 | 标注「上报人已修改」 |
| 6 | AI 识别与确认 | 点击「确认并提交」 | 生成工单 `T-YYYYMMDD-xx`，进入进度页 |
| 7 | 处理进度 | 查看时间轴 | 状态按治理端动作推进 |
| 8 | 处理进度 | 查看处置结果与积分 | 已办结时显示结果与积分 |

### 2.2 紧急上报（分支）

| 步骤 | 触发条件 | 系统行为 |
| --- | --- | --- |
| 1 | 描述命中紧急词表（火灾、打架、伤者、交通事故、燃气泄漏等） | 风险等级直接置为「紧急」 |
| 2 | 确认页 | 顶部显示红色应急卡，列出 110 / 119 / 120 / 122 |
| 3 | 确认页 | 主按钮变为「我已联系法定渠道，继续留存线索」 |
| 4 | 提交后 | 工单标记 `emergency=true`，同时抄送治理端应急提示条 |
| 5 | 结果 | 提示：AI 与平台不替代法定应急渠道 |

### 2.3 状态语义

| 状态 | 含义 | 上报人可见文案 |
| --- | --- | --- |
| `ai_processing` | AI 处理完成，等待上报人确认 | 待你确认 |
| `submitted` | 已提交，等待治理人员确认 | 已受理 |
| `need_info` | 治理人员退回补充 | 需补充信息 |
| `dispatched` | 已分派处置主体 | 已分派 |
| `processing` | 处置中 | 处置中 |
| `resolved` | 已办结并反馈 | 已办结 |
| `transferred` | 已转交其他主体 | 已转交 |

## 3 治理端流程

```text
事件列表 / 地图
      │
      ├─ 看 AI 建议（摘要、类别、风险、重复候选、建议处置主体）
      │
      ├─ 人工决定 ──┬─ 确认并分派 ──► 选择处置主体 + 期限 ──► 通知上报人「已分派」
      │             ├─ 退回补充 ────► 填写所需补充内容 ──► 通知上报人「需补充信息」
      │             └─ 转交 ───────► 选择转交对象 ──────► 通知上报人「已转交」
      │
      └─ 处置与反馈 ──► 填写处理结果 + 是否计积分 ──► 通知上报人「已办结」
```

要点：

1. **AI 建议区块与人工决定区块在视觉上分离**，AI 区块使用虚线边框与「AI 建议，需人工确认」标签。
2. 确认分派时，处置主体默认选中 AI 建议项，但必须由人工点击「确认并分派」才生效。
3. 紧急事件在列表与详情页顶部固定显示应急渠道提示条，不提供「确认分派」以外的自动动作。

## 4 仿真端流程

```text
选择情景（S0 / S1 / S2 / S3）
      │
      ├─ 查看该情景唯一新增机制
      ├─ 查看六项指标对比（当前为占位数据）
      ├─ 展开参数与假设（标注来源或项目假设）
      ├─ 调整参数权重（演示用，可一键恢复默认）
      └─ 阅读结果局限说明
```

情景切换只改变治理机制，其余参数保持一致。

## 5 界面状态机（原型实现）

```text
#/rider/home ──► #/rider/report ──► #/rider/ai-review ──► #/rider/progress
     ▲                │                    │                    │
     │                │                    ├─(紧急)─► 应急卡（同页展示）
     └────────────────┴────────────────────┴────────────────────┘
                                  #/rider/services

#/gov/events ──► #/gov/events/:id ──►（人工动作）──► 列表状态更新
#/gov/map
#/gov/metrics

#/sim/compare ──► #/sim/config ──► #/sim/limits
```

- 通过 URL hash 直接进入任意屏幕，便于录屏与截图。
- 所有状态保存在浏览器 `localStorage`，刷新不丢失，便于分段录屏。
- 演示控制台提供「重置演示数据」，恢复初始虚构数据。

## 6 关键交互规则

| 规则 | 说明 |
| --- | --- |
| 不可跳过 AI 确认 | 上报页的「AI 识别」是提交前的唯一通道 |
| 不可自动分派 | 治理端不存在「自动确认」按钮 |
| 紧急优先 | 命中紧急词表时普通提交按钮被替换；提交后进入专用留存页（`#/rider/emergency-confirm`），不进入普通进度视图 |
| 仿真限定语常驻 | 仿真端每页显示数据来源、重复次数与「第一轮合成仿真」限定语；数值附 95% 区间 |
| 待补材料可见 | 未产出的敏感性分析、最终汇总、平台复跑以 `SIM_RESULT_NEEDED_*` 标注，界面声明不以估计值代替 |
| 演示数据可见 | 服务点、积分、驿站均标注「演示数据」 |
| 可重置 | 演示控制台一键恢复初始状态 |

## 7 异常与边界处理

| 情况 | 处理 |
| --- | --- |
| 未输入任何内容即点击 AI 识别 | 按钮禁用并提示「请先语音、拍照、定位或输入文字」 |
| 描述命中多个类别 | 展示主类别与次类别，允许人工切换 |
| 重复工单 | 确认页提示「与 T-… 可能重复」，用户可选择合并或继续单独上报 |
| 位置缺失 | AI 使用「手工填写的定位备注」并降低位置置信度提示 |
| 治理端退回补充 | 骑手端进度页显示待补充项；原型不实现回填表单，标注为第二轮范围 |
| 事件被转交 | 时间轴新增转交节点，责任主体更新 |
