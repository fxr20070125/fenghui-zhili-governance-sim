所有人物、城市问题和结果均为合成数据。现有调研材料只支持角色设定与机制方向，不支持将仿真比例表述为现实统计或政策因果效果。

## 2. 实验设计

| 项目 | 设置 |
|---|---|
| 唯一干预 | `scenario_id` 对应 S0、S1、S2、S3 |
| S0 | 零散上报，不启用 AI 结构化、透明反馈或服务激励 |
| S1 | 增加 AI 脱敏、结构化、去重、分类和建议分派 |
| S2 | 在 S1 上增加治理进度与结果反馈 |
| S3 | 在 S2 上增加按需非现金服务信息 |
| 配对控制 | 同一 run 使用相同人群、问题流和随机事件键，只改变机制 |
| 重复规模 | 每个情景 20 次，共 80 次 |
| 单次规模 | 240 名合成从业者，56 个模拟日 |
| 安全约束 | 紧急事件走法定渠道；AI只建议，正式治理决定由人工关口确认 |

## 3. 主要量化结果

| 情景 | 有效上报率 | 重复或无效率 | 分派准确率 | 平均处置时间 | 平均上报耗时 | 最后两周参与率 | 独立问题覆盖率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| S0 | 53.5% | 46.5% | 64.6% | 51.66小时 | 8.01分钟 | 12.2% | 15.3% |
| S1 | 71.9% | 28.1% | 85.2% | 32.39小时 | 3.00分钟 | 29.6% | 41.8% |
| S2 | 71.4% | 28.6% | 85.7% | 27.20小时 | 3.00分钟 | 40.2% | 52.2% |
| S3 | 70.1% | 29.9% | 85.2% | 27.16小时 | 3.00分钟 | 49.3% | 59.6% |

关键配对变化：

- S0→S1：有效上报率增加 18.4 个百分点，重复或无效率下降 18.4 个百分点，分派准确率增加 20.6 个百分点，平均上报耗时减少 5.01 分钟。
- S1→S2：平均处置时间减少 5.19 小时，最后两周参与率增加 10.6 个百分点，独立问题覆盖率增加 10.4 个百分点。
- S2→S3：独立问题覆盖率增加 7.4 个百分点，最后两周参与率增加 9.1 个百分点；有效上报率反而下降 1.3 个百分点。
- S0→S3：有效上报率增加 16.6 个百分点，分派准确率增加 20.6 个百分点，平均处置时间减少 24.50 小时，独立问题覆盖率增加 44.3 个百分点，最后两周参与率增加 37.1 个百分点。

## 4. 建议解释

在当前合成参数下，AI辅助首先降低信息摩擦并改善结构化和分派；透明反馈主要改善处置表现和持续参与；按需服务进一步扩大问题覆盖与后期参与。S2→S3 中有效上报率小幅下降、覆盖率和持续参与却继续上升，说明激励可能吸引更多原本处于参与边缘、信息完整性较低的报告。最终方案应把它表述为“覆盖范围与信息质量之间的治理权衡”，而不是宣称所有指标单调改善。

群体参与差距没有显示稳定改善：S2→S3 的配对变化为 -0.03 个百分点，95% 区间为 [-1.90, 1.84]，跨越 0。因而只能说“当前实验未发现明确缩小差距的证据”，不能声称服务激励已经实现公平改善。

## 5. 玉兰万象补充验证

玉兰万象快速版使用 `OneSim(qwen)`，形成 4 类 Agent、11 个动作并完成模板代码生成和语法验证。S3 运行 ID 为 `20260915_232232`，5 次独立运行共执行 55 次决策，平台记录 55/55 成功。这说明方案可以迁移到官方多智能体平台并完成端到端事件链。

但本次自动生成代码只让治理 Agent 返回推理文本，没有把审核、派单、反馈和奖励写回 `case_state`；跨轮 `metrics_container` 也未稳定传递，最终报告明确显示未采集到自定义指标。因此玉兰结果只作为“平台可运行性与数据流风险”的补充，不能与本地 S0—S3 数值混合平均，也不能作为 S3成效证明。源码、平台报告和逐文件审计均已归档。

## 6. 安全与治理边界

- AI只负责信息脱敏、结构化、分类、去重、风险提示和建议分派，不替代行政人员作出正式决定。
- 火灾、严重事故、治安冲突和急救事件提示 110、119、120 或 122，不进入普通工单。
- 数据最小化：不保存真实姓名、手机号、车牌、精确住址或连续轨迹；本实验全部使用合成标识。
- 非现金服务只包括驿站、换电、托管等公共服务信息，不使用现金或商业派单优待诱导上报。
- 仿真只能用于比较机制方向和发现风险，不能替代真人调研、行政试点或政策效果评估。
