# 蜂汇智理：玉兰万象快速版后续任务清单

## 0 当前任务处理

1. 若旧图传播数据连续20分钟停在同一节点，停止旧任务并保留日志或截图。
2. 不删除旧场景，改名为“蜂汇智理-完整版-暂停”。
3. 新建“蜂汇智理-快速版-v1”，使用 `onesim-fast-scenario-prompt.md`。

## 1 场景与研究目标

- 粘贴快速版概括描述。
- 研究目标只设置1个自变量 `scenario_id` 和8个因变量。
- 粘贴4类Agent描述和11节点交互描述。
- 保存后再进入行为图。

验收：页面中能找到4类Agent；三轮、人工审核、应急分流、八项指标均在文字中明确出现。

## 2 图骨架

1. 点击“生成图骨架”。
2. 数量必须为4类Agent、11个动作节点，动作顺序与输入稿一致。
3. 必须单链、无回边、无提前结束。
4. 点击“验证”。只有验证通过才继续。

预计：5—15分钟。

## 3 图传播数据

1. 点击“生成图传播数据”。
2. 检查每条事件的顶层字段。通常应为4个对象，绝不能重新出现27个独立字段。
3. 检查每个动作只有1个Mapping；单入边动作不应使用等待多路输入的`trigger=all`。
4. 检查三轮记录采用append，人工关口和应急规则正确。
5. 点击“验证”。

预计：10—30分钟；若30分钟仍未完成但日志持续换节点，可再等15分钟；同一节点停20分钟则视为卡住。

## 4 Agent画像

1. 只建立4个主本实例：ScenarioController、NewEmploymentWorker批次、GovernanceWorkflow、MetricRecorder各1个。
2. 使用快速版输入稿中的合成JSON；不得填写真实姓名、电话、车牌、地址或行动轨迹。
3. 勾选“直接采用主本”，暂不生成大量副本。
4. 确认worker批次中至少有2名骑手和2名司机，否则不能计算群体参与差距。

预计：10—20分钟。

## 5 仿真代码

1. 点击“生成代码”，完成后执行平台代码审查或校验。
2. 搜索并核对四个对象名：`scenario_config`、`worker_profile`、`case_state`、`metrics_container`。
3. 搜索 `human_review_confirmed`，确认没有在该值为false时创建普通工单。
4. 搜索 `ground_truth_emergency` 或应急判断，确认紧急事件不会进入普通处置。
5. 搜索records追加逻辑，确认三轮使用append而非覆盖。
6. 搜索八个因变量名称，确认均有输出，分母为0时返回null。

预计：生成5—15分钟，人工检查10—20分钟。

## 6 S0—S3直接正式运行

不单独安排冒烟测试，也不为四个情景重复生成行为图、传播数据、画像或代码。只使用同一个快速版场景和同一份生成代码，按S0、S1、S2、S3顺序完成正式运行。

1. 在ScenarioController主本中设置`scenario_id=S0`，由程序自动得到三个false开关；不要手工改人物、问题或治理能力。
2. 直接运行5次独立正式实验，每次仿真循环数设为1。行为图内部已经包含三次问题发现机会，不要把循环数设为3。
3. 运行结束后立即导出并命名S0文件，防止下一情景覆盖结果。
4. 只把scenario_id改为S1，再运行5次并导出；随后以同样方式完成S2和S3。
5. 切换scenario_id后不重新生成图骨架、图传播数据或代码。三个机制开关必须由scenario_id映射产生：S0=(false,false,false)，S1=(true,false,false)，S2=(true,true,false)，S3=(true,true,true)。
6. 每次独立运行开始必须重置`current_trust=initial_trust`并清空`metrics_container.records`；每次运行结束应有4人×3轮=12条个体记录。
7. 记录平台模型名称、运行日期、情景、运行编号以及平台可提供的随机种子。

每个情景5次，共20次正式运行。若平台支持在同一启动任务中设置5个独立运行轮次，优先批量启动；若不支持，再手动运行5次。任何一次失败都标记为失败并保留日志，不得挑选性删除后只报告成功结果。

机制核对：

| 情景 | AI辅助 | 透明反馈 | 非现金服务 |
|---|---:|---:|---:|
| S0 | 否 | 否 | 否 |
| S1 | 是 | 否 | 否 |
| S2 | 是 | 是 | 否 |
| S3 | 是 | 是 | 是 |

## 7 导出与归档

每个情景至少保存：

- 原始事件日志；
- 个体决策与三轮记录；
- 八项指标结果；
- 平台生成的分析报告；
- 图骨架、传播验证、画像、运行结果关键截图；
- 失败或重试日志。

文件放入 `simulation/evidence/onesim-export/`，建议命名：

```text
S0_run01_events.csv
S0_run01_metrics.json
S0_run01_log.txt
S0_run01_result.png
```

## 8 结果检查与汇总交接

AI2负责先做实验审计：

- 比较S0—S3是否只改变机制开关；
- 检查每组运行次数相同；
- 检查是否有缺失轮次、重复广播、提前终止或异常null；
- 计算各指标均值、波动和机制间差异；
- 明确标注“合成仿真，不是现实调查”。

审计通过后，把导出文件、指标表、关键截图和限制说明交给AI4汇总。AI4不得只引用平台自动报告，必须同时引用原始导出和实验配置。

## 9 时间预算

| 阶段 | 目标时间 |
|---|---:|
| 场景填写与骨架 | 10—20分钟 |
| 图传播数据 | 10—30分钟 |
| 画像 | 10—20分钟 |
| 代码生成与检查 | 15—35分钟 |
| S0—S3共20次正式运行 | 视平台负载，约1—4小时 |

30分钟目标只针对最容易失控的“图传播数据”步骤。后续应分阶段保存，任何阶段失败都从最近保存点继续，不要从第一步整体重做。
