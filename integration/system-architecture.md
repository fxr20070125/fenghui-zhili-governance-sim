# 蜂汇智理总体系统架构

## 架构目标

系统围绕“低成本上报、AI 辅助处理、人工治理决定、结果透明反馈、机制仿真评估”形成闭环。AI 负责信息整理和建议，不替代治理人员作出行政或应急决定；严重事故、火灾、治安与急救事件退出普通工单流程，提示使用 110、119、120 或 122。

## 业务闭环

```text
骑手或司机发现问题
  -> 语音 文字 图片 位置上报
  -> 本地提示与用户确认
  -> AI 脱敏 结构化 重复合并 分类 风险分级 建议分派
  -> 治理人员人工确认 退回补充 转交或派单
  -> 社区 街道 市级责任主体处置
  -> 进度与结果反馈
  -> 服务型积分或权益记录
  -> 匿名化事件与机制数据进入仿真和评估
```

## 逻辑分层

| 层级 | 核心组件 | 输入 | 输出 | 控制点 |
| --- | --- | --- | --- | --- |
| 交互层 | 骑手端、治理端、仿真端 | 上报、确认、处置、参数 | 状态、提示、图表 | 明示数据用途；禁止真实敏感演示数据 |
| 接入层 | 文本、语音、图片、位置适配 | 多模态材料 | 标准事件包 | 最小化采集；用户可修改或取消 |
| AI 处理层 | 脱敏、摘要、实体抽取、去重、分类、风险、建议路由 | 标准事件包 | AI 建议包 | 输出置信度和依据；不得自动结案 |
| 工单层 | 人工复核、责任路由、状态机、反馈 | AI 建议包 | 可执行工单 | 人工决定；所有修改留痕 |
| 服务激励层 | 积分、驿站权益、托管优先权等 | 已核验贡献 | 权益建议与记录 | 避免现金化、攀比和强迫参与 |
| 仿真层 | 智能体、S0–S3、重复运行、敏感性分析 | 匿名化结构、项目假设 | 六项指标与波动 | 合成数据显式标识；结果可复现 |
| 治理与审计层 | 权限、日志、留存、删除、异常与应急规则 | 全链路事件 | 审计记录 | 最小权限；敏感字段隔离；可追责 |

## 核心数据对象

### 上报事件

- `event_id`：随机标识，不使用手机号或身份证生成。
- `report_channel`：语音、文字、图片或位置。
- `raw_payload_ref`：原始材料的受控引用，不进入普通分析导出。
- `redacted_text`：已脱敏文本。
- `location_precision`：精确位置或降精度区域。
- `user_confirmed`：上报人是否确认结构化结果。

### AI 建议包

- `summary`、`category`、`risk_level`、`duplicate_group`。
- `suggested_owner_level`：社区、街道或市级。
- `confidence` 与 `reason_codes`。
- `emergency_redirect`：是否退出普通流程及法定渠道提示。

### 治理工单

- `reviewer_decision`、`assigned_owner`、`status`、`timeline`。
- `correction_reason`：人工修改 AI 建议的原因。
- `resolution` 与可公开反馈摘要。

### 仿真实验

- `scenario_id`：S0、S1、S2、S3。
- `model_version`、`parameter_set`、`random_seed`、`run_id`。
- 六项固定指标及原始日志引用。

## S0 至 S3 的系统差异

| 场景 | AI 上报处理 | 透明反馈 | 差异化服务激励 |
| --- | --- | --- | --- |
| S0 现状基准 | 无统一处理 | 无持续反馈 | 无 |
| S1 AI 上报 | 有 | 无新增机制 | 无 |
| S2 AI 上报加透明反馈 | 有 | 有责任主体、进度和结果 | 无 |
| S3 AI 上报加透明反馈加差异化激励 | 有 | 有 | 有积分、驿站权益、托管优先权等 |

除表中新增机制外，仿真中的人群、事件、时间范围和其他参数应保持一致。

## 部署与边界

第一版按演示型最小系统设计，可采用本地或隔离测试环境、虚构数据和脱敏素材。不得宣称已接入政府、物业或商业平台生产系统，不做城市级导航，不改造商业派单算法，不自动处理交通事故或人身安全事件。
